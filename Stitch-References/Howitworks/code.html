Stage 03 // Execution Guard

3. Ephemeral Docker Sandboxing

~120s limit

Complete hardware & socket isolation. Code is run with zero internet access, non-root privileges, and constrained resource boundaries.

  • check_circle Mounts source into a locked-down, unprivileged Docker container (uid: 10001).
  • check_circle Applies strict limits: 512MB RAM, 1 vCPU ceiling, read-only rootfs, and 120s execution watchdog.
  • check_circle Executes npm ci and npm test, capturing unbuffered raw stdout/stderr and process exit codes.

4. Evidence-Based Report Generation

Deterministic

No heuristics or ambiguous evaluations. Every score is directly mapped from verified compiler outputs, test exit codes, and hashes.

  • check_circle Compiles observed exit codes, file verifications, and test suites into an immutable ledger.
  • check_circle Labels checks objectively: Passed, Failed, or Not Verified.
  • check_circle Produces self-contained, offline-auditable standalone HTML reports and standard JSON exports.

Security Boundaries & Guarantees

Engineered from the ground up for strict confidentiality and host environment protection.

lock Zero Leak Protocol
terminal
Host System Isolation

Uploaded code never executes directly on your host operating system. All build hooks and npm post-install scripts run exclusively within jail-confined container cgroups.

delete_forever
Immediate Teardown

Ephemeral containers, virtual volumes, and temporary unzipped directories are strictly destroyed immediately upon audit completion or execution timeout.

rule
Strict 'Not Verified' Semantics

'Not Verified' strictly signals missing empirical evidence or unconfigured test scripts. BuildProof never falsely passes unexercised or untestable codebase components.

cloud_off
No Third-Party Transmission

No code or project files are transmitted to external cloud services or third-party servers. Audits are calculated entirely on your designated local or on-prem execution daemon.
